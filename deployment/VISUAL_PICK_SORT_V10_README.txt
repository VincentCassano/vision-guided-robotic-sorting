操作
新包完整复制到~/test后执行配套VISUAL_PICK_SORT_V10_ONSITE_COMMAND.txt。
1. 当前手必须确已空，退出其他控制；相机/板/安装不变，空手范围清空，现场守急停。e确认，非空/不确定用q。
2. S/Q采当前目标，m高位对准、d下降、p确认非接触；保持同一空壳在采图位置，不能搬回旧槽。
3. 确认空壳由板/槽承托全部重量，撤开双手，c只做初始闭指，臂不动。
   没有本机成功配方时起始候选[27500,31500,27000,19000,65535,64556]，不能称为已抓稳。
4. 在终端输入t+/t-/i+/i-/m+/m-/r+/r-并回车，每次只调一个弯曲通道250逻辑单位。
   t=拇指，i=食指，m=中指，r=无名指；+=增加弯曲，-=减少弯曲。小拇指和对掌不写。
   显示目标、实际位置、电流、状态及上一步结果。等待调节输入时持续只读监测手和臂，不把旧组当新反馈。
   候选上限分别30000/31500/29500/20250；食指不再超过已观察31500，无名指不再直接发20500。
   这些是本次监督调节范围，不是厂家安全持力认证；status5阻止对应指继续加弯，达到上限只拒绝该次请求。
   每步均核对原目标±2/实际±150、其他五通道、单指扫掠、三组至少1秒静稳、身份/诊断/电流及状态。
   实际3/4、超流、通信、保护、帧/限位/漂移异常仍中止，不清保护/复位/自动加紧或故障松手。
5. 手型确认后g一次授权：当前握持反馈合格→竖直提140mm(5%)→三个MoveJ-P连接1/1/0(r0、10%)→后移40mm黑框五指张开。
   事先确认含物上升与整条转运通道预计余量至少20mm；g后无新的正常键盘等待，控制器r0仍可能减速过角。
   若目视漏抓，在终端按f并回车，请求软件停止/取消后续投放；不自动松指。q回车也请求停止。
   软件请求不是已验证的即时硬件停止；非受控运动、明显升温或来不及输入时现场硬件急停。
6. 正常张开后u=亲眼确认实际入黑框且手空，并空返；e=实际入框且手空并结束；f=未夹起/未投进且手空，仅记失败。
   不确定/仍持物用q，不把空手跑路线算成功。
7. 原始结果始终保存本机captures/visual_pick_sort_v10_*.zip；可以留在本机，不要求回传开发端才能继续。
   只有整轮正常完成且现场u/e确认实际入框，才更新calibration/visual_grip_accepted.json。
   下次同一入口自动读取它，核对源ZIP SHA/内部哈希、实际成功记录、配置和当前交付，再复用该起始手型。
   失败不覆盖已有成功手型；--new-tune可忽略旧配方重新调。程序直接从成功记录推导目标，不盲信JSON中可修改的recipe字段。

边界
这是现场调节并接完整流程的入口，不是已经解决实际持力，也没有自动物体保持/漏抓传感器。
抓取与漏抓结果由现场观察确认；f只响应现场失败报告，不声称能自主发现空手。
仅45.8±0.1mm×98mm惰性黑壳、同高工作面、固定头/底座/安装、已知预抓腕姿与任务修正范围。
完整六维/TCP/RGBD、多类批次、通用扫掠与长期成功率未验收。
SDK仅在机器人Linux aarch64独立worker加载；本地仅人工源码核对及文件CRC/SHA，不运行项目离线测试/编译/AST/mock/FK/IK。
